## Phase 1 implications

- **django/django** alone accounts for 15/30 empty-patch instances. Phase 1's hierarchical localization MUST avoid passing the full repo skeleton to the reranker on these instances; aggressive summarization (one-line per file, top-N directories only) is required.

- 11/30 hit V7's turn limit (`stop_reason='turn_limit'` or `n_turns >= 50`). Phase 3's agent path with `T_max_hard=50` (V10_DESIGN.md §3.4) needs a per-turn cost guard that triggers BEFORE the turn limit on these instances — otherwise the same empty-patch failure mode reappears in V10.
- Issue length distribution: 2/30 have problem_statement < 500 chars. Short issues + huge repos = localization is the bottleneck (the issue text doesn't constrain the search; the repo skeleton must do most of the narrowing). Phase 1's traceback parser (Stage 1c) and symbol grep (Stage 1d) are most valuable when the issue is short — these instances are the test case for whether localization actually works.

**Conclusion:** the empty-V7 instances are concentrated in large repos (django + sympy = ~83%) and frequently hit turn limits. Phase 1's localizer must compress the skeleton aggressively for these repos, and Phase 3's agent must finalize on partial candidates rather than time out empty-handed. Both are explicit in V10_DESIGN.md but worth re-confirming as Phase 1 acceptance criteria.
