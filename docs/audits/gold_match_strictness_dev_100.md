# Gold-patch matcher strictness audit (Dev-100)

Generated by `scripts/audit_gold_match_strictness.py`. For each dev-100 instance, classifies every claimed hit at top-K by the tightest match type that holds:

  - **exact** — `gold == retrieved` literally
  - **normalized** — equal after stripping leading `./` and `/`
  - **suffix** — `retrieved.endswith('/' + gold)` (lenient)
  - **prefix** — gold path is a directory containing retrieved (or vice versa)
  - **basename** — same filename, different parent directories
  - **none** — not actually a hit

Per V10_DESIGN.md, the production matcher in `harness.eval.evaluate_retrieval_recall` does set-membership of normalized paths — so it accepts only `exact` and `normalized` matches. Anything classified as `suffix`, `prefix`, or `basename` here would be a MISS by the production matcher; the audit is checking whether such cases also got counted as hits (i.e., whether there's a leak).
